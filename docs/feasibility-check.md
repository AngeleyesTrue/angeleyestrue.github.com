# 기능별 가능성 검증 결과

## 1. ✅ Supabase Storage 사진 업로드

### 가능성: 완전히 가능
**근거**: Supabase 공식 문서에서 클라이언트 사이드 업로드 완전 지원

#### 구현 방식
```javascript
// 기본 업로드 (6MB 이하)
const { data, error } = await supabase.storage
  .from('avatars')
  .upload('public/avatar1.png', file, {
    cacheControl: '3600',
    upsert: false
  })

// 대용량 파일 (resumable upload)
import { Upload } from '@aws-sdk/lib-storage'
// TUS 프로토콜 지원으로 중단된 업로드도 재개 가능
```

#### 주요 특징
- **파일 크기**: 최대 500GB (유료 플랜)
- **업로드 방식**: 표준 업로드, Resumable Upload, S3 호환
- **진행률 추적**: onProgress 콜백 지원
- **자동 썸네일**: Transform API로 리사이징 가능
- **CDN 지원**: 전 세계 배포 가능

#### 보안 설정
```sql
-- Storage RLS 정책 (완전히 지원됨)
CREATE POLICY "사용자별 폴더 업로드 제한" ON storage.objects
  FOR INSERT WITH CHECK (auth.uid()::text = (storage.foldername(name))[1]);
```

## 2. ✅ 관리자 권한 판별 시스템

### 가능성: Custom Claims + RLS로 완전 구현 가능
**근거**: Supabase Auth Hook과 JWT Custom Claims 공식 지원

#### 구현 방식

**A. 데이터베이스 설계**
```sql
-- 사용자 역할 테이블
CREATE TABLE user_roles (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES auth.users ON DELETE CASCADE NOT NULL,
  role VARCHAR(20) NOT NULL, -- 'admin', 'user'
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE (user_id, role)
);

-- 기본 관리자 등록
INSERT INTO user_roles (user_id, role) 
VALUES ('your-user-id', 'admin');
```

**B. Auth Hook 설정**
```sql
-- JWT에 관리자 정보 추가하는 Hook
CREATE OR REPLACE FUNCTION public.custom_access_token_hook(event jsonb)
RETURNS jsonb LANGUAGE plpgsql AS $$
DECLARE
  claims jsonb;
  user_role text;
BEGIN
  -- 사용자 역할 조회
  SELECT role INTO user_role 
  FROM public.user_roles 
  WHERE user_id = (event->>'user_id')::uuid;
  
  claims := event->'claims';
  
  -- JWT에 role 정보 추가
  IF user_role IS NOT NULL THEN
    claims := jsonb_set(claims, '{user_role}', to_jsonb(user_role));
  END IF;
  
  event := jsonb_set(event, '{claims}', claims);
  RETURN event;
END;
$$;
```

**C. 클라이언트에서 권한 확인**
```javascript
import { jwtDecode } from 'jwt-decode'

function useAuth() {
  const [user, setUser] = useState(null)
  const [isAdmin, setIsAdmin] = useState(false)
  
  useEffect(() => {
    supabase.auth.onAuthStateChange((event, session) => {
      if (session) {
        const jwt = jwtDecode(session.access_token)
        setUser(session.user)
        setIsAdmin(jwt.user_role === 'admin')
      }
    })
  }, [])
  
  return { user, isAdmin }
}
```

**D. RLS 정책에서 관리자 확인**
```sql
CREATE OR REPLACE FUNCTION is_admin()
RETURNS BOOLEAN AS $$
BEGIN
  RETURN (auth.jwt() ->> 'user_role') = 'admin';
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- 관리자만 접근 가능한 테이블 정책
CREATE POLICY "관리자만 접근" ON profile_links
  FOR ALL USING (is_admin());
```

## 3. ✅ 무한 계층 태그 시스템

### 가능성: PostgreSQL의 재귀 쿼리로 완전 구현 가능
**근거**: PostgreSQL WITH RECURSIVE 및 ltree 확장 지원

#### 구현 방식

**A. 기본 재귀 구조**
```sql
CREATE TABLE tags (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(50) NOT NULL,
  parent_id UUID REFERENCES tags(id),
  user_id UUID REFERENCES auth.users(id),
  depth INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 경로 자동 생성 (Generated Column)
ALTER TABLE tags ADD COLUMN path TEXT GENERATED ALWAYS AS (
  CASE 
    WHEN parent_id IS NULL THEN name
    ELSE (
      WITH RECURSIVE tag_path AS (
        SELECT id, name, parent_id, name as path
        FROM tags WHERE id = tags.id AND parent_id IS NULL
        UNION ALL
        SELECT t.id, t.name, t.parent_id, tp.path || '/' || t.name
        FROM tags t
        JOIN tag_path tp ON t.parent_id = tp.id
      )
      SELECT path FROM tag_path WHERE id = tags.id
    )
  END
) STORED;
```

**B. 고급 ltree 방식 (더 효율적)**
```sql
-- ltree 확장 활성화
CREATE EXTENSION IF NOT EXISTS ltree;

CREATE TABLE tags (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(50) NOT NULL,
  parent_id UUID REFERENCES tags(id),
  path ltree, -- '개발.csharp.web.aspnet' 형태
  user_id UUID REFERENCES auth.users(id)
);

-- 효율적인 계층 쿼리
-- 모든 하위 태그 조회
SELECT * FROM tags WHERE path <@ '개발.csharp';
-- 직접 하위 태그만 조회  
SELECT * FROM tags WHERE path ~ '개발.csharp.*{1}';
```

**C. 클라이언트 사이드 구현**
```javascript
// 무한 드릴다운 가능
async function getTagChildren(parentId = null) {
  return await supabase
    .from('tags')
    .select('*')
    .eq('parent_id', parentId)
    .order('name')
}

// 전체 경로로 태그 찾기
async function getTagByPath(path) {
  return await supabase
    .from('tags')
    .select('*')
    .eq('path', path)
    .single()
}

// 계층 구조 시각화
function TagTree({ parentId = null, depth = 0 }) {
  const { data: children } = useQuery(['tags', parentId], 
    () => getTagChildren(parentId))
  
  return (
    <div style={{ marginLeft: depth * 20 }}>
      {children?.map(tag => (
        <div key={tag.id}>
          <span>{tag.name}</span>
          <TagTree parentId={tag.id} depth={depth + 1} />
        </div>
      ))}
    </div>
  )
}
```

## 4. ✅ 임시 URL 생성 및 만료 시스템

### 가능성: 완전히 가능 (클라이언트 사이드 구현)
**근거**: JavaScript Date 객체와 Supabase 필터링 기능

#### 구현 방식

**A. Short Code 생성**
```javascript
function generateShortCode(length = 6) {
  const chars = 'abcdefghijklmnopqrstuvwxyz0123456789'
  let result = ''
  for (let i = 0; i < length; i++) {
    result += chars.charAt(Math.floor(Math.random() * chars.length))
  }
  return result
}

// 중복 체크 포함 안전한 생성
async function createUniqueShortCode() {
  let code
  let exists = true
  
  while (exists) {
    code = generateShortCode()
    const { data } = await supabase
      .from('profile_links')
      .select('id')
      .eq('short_code', code)
      .single()
    exists = !!data
  }
  
  return code
}
```

**B. 만료 시스템**
```javascript
// 링크 생성 (관리자만)
async function createProfileLink(title, daysToExpire = 30) {
  const shortCode = await createUniqueShortCode()
  const expiresAt = new Date()
  expiresAt.setDate(expiresAt.getDate() + daysToExpire)
  
  return await supabase.from('profile_links').insert({
    short_code: shortCode,
    title,
    expires_at: expiresAt.toISOString(),
    created_by: user.id
  })
}

// 링크 유효성 검증
async function validateProfileLink(shortCode) {
  const { data, error } = await supabase
    .from('profile_links')
    .select('*')
    .eq('short_code', shortCode)
    .eq('is_active', true)
    .gt('expires_at', new Date().toISOString()) // 만료 시간 확인
    .single()
    
  return { isValid: !!data, linkData: data }
}
```

**C. React Router와 연동**
```javascript
// 동적 라우팅으로 처리
function CareerProfileRoute() {
  const { shortCode } = useParams()
  const [linkData, setLinkData] = useState(null)
  const [isLoading, setIsLoading] = useState(true)
  const [error, setError] = useState(null)
  
  useEffect(() => {
    if (shortCode) {
      validateProfileLink(shortCode)
        .then(result => {
          if (result.isValid) {
            setLinkData(result.linkData)
            // 접근 로그 기록
            logProfileAccess(result.linkData.id)
          } else {
            setError('링크가 만료되었거나 유효하지 않습니다')
          }
        })
        .finally(() => setIsLoading(false))
    }
  }, [shortCode])
  
  if (isLoading) return <Loading />
  if (error) return <ErrorPage message={error} />
  if (!linkData) return <AccessDeniedPage />
  
  return <CareerProfile linkData={linkData} />
}
```

## 6. ✅ GitHub Pages 배포

### 가능성: 모든 기능이 GitHub Pages에서 동작 가능
**근거**: 클라이언트 사이드 API 호출과 CORS 지원

#### GitHub Pages 제약사항 및 해결책

- **정적 파일만**: 모든 로직이 클라이언트 사이드라서 문제없음
